# AI Bridge v1.2 — Closing the Loop, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the hand-off loop visible inside Burp — the hunter sees what agents picked up and what they replied, and the shared files scale safely over months of real hunting.

**Architecture:** No daemon, same as v1.1.1. The extension now also *reads* two things it previously only wrote: `archive/` (consumption) and a new agent-controlled `results.jsonl` (replies, keyed to the batch id already in the manifest). Sent-state codec grows one field and resets cleanly at v2.

**Tech Stack:** Java 21, Montoya API 2025.5, Swing, headless unit tests against real temp folders and reflection-proxied API fakes.

**Spec:** this document; contract reference in `docs/agent-protocol.md`.

## Global Constraints

- No new files written by the extension into the inbox root other than the existing pair + manifest; agents get exactly one new writable file (`results.jsonl`), documented in the protocol.
- Nothing that exists is renamed; agent contract changes are additive only.
- Every extension behavior added here ships with a headless test that fails when the behavior regresses; tests run in `build.sh` and CI.
- Public docs stay neutral (`api.example.com`); no real target hostnames anywhere.
- JPEG-free repo: visuals as SVG only.

## Review Focus

1. `results.jsonl` truncated mid-line by a concurrent writer → reader must skip the torn line, never crash, never re-report old lines (test pins offset/watermark behavior).
2. Extension unloaded/loaded (same Burp session) → state restores, `results.jsonl` watermark resumes from 0 (catch-up re-parse must be idempotent).
3. Manifest rotated while an agent holds an open file descriptor → agent sees old inode or EOF, never a persistent 404; live manifest always ends with a `rotated` event pointing at the archive.
4. Checkboxes after restore → state visible in the UI on first paint (ctor reads bridge flags, not hard-coded).
5. Inbox on a filesystem without POSIX permissions (Windows) → `hardenInbox` must be a no-op, not an exception path that kills initialization.
